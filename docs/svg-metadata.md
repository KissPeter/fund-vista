# Ownership / licence metadata in generated SVGs

Every deliverable SVG can carry a notice saying who made it and on what terms,
in the places SVG defines for it:

| Element | Content |
|---|---|
| `<title>` | per-request title (CLI: the file name) |
| `<desc>` | description + rights line + "Generated by fund-vista penplot." |
| `<metadata>` → RDF | Dublin Core `dc:creator`, `dc:rights`, `dc:title`; Creative Commons `cc:license`, `cc:attributionName`, `cc:attributionURL`, and the licence terms (`cc:permits` / `cc:requires` / **`cc:prohibits CommercialUse`**); `xmp:CreatorTool` for the generator |

Plotters, vpype and browsers ignore all of it; the geometry is unchanged.

**It is a notice, not protection.** Editors and optimisers (svgo) can strip
metadata. It records authorship and terms (and makes your position explicit);
copyright itself exists without it. For marks that survive stripping use the
title-block label (plotted text) or a signature stroke.

## Configure (server-side, off by default)

```bash
PENPLOT_SVG_CREATOR="Pen Pixel Shop"
PENPLOT_SVG_RIGHTS="(c) 2026 Pen Pixel Shop. No commercial use without written permission."
PENPLOT_SVG_LICENSE=cc-by-nc-4.0          # see presets below; or all-rights-reserved
PENPLOT_SVG_LICENSE_URL=                   # optional custom terms URL (http/https)
PENPLOT_SVG_ATTRIBUTION_URL=https://example.org/pen   # optional credit link
```

Presets (`PENPLOT_SVG_LICENSE`): `all-rights-reserved`, `cc-by-nc-4.0` (no
commercial use), `cc-by-nc-nd-4.0` (no commercial use, no derivatives),
`cc-by-nc-sa-4.0`, `cc-by-4.0`, `cc-by-sa-4.0`. "No commercial use" is the
Creative Commons **NonCommercial** term; for "nobody may use it without my
permission" choose `all-rights-reserved` and say so in `PENPLOT_SVG_RIGHTS`.
An unknown preset or a non-http(s) URL fails at startup.

Behaviour:

- **Nothing set → nothing added**: output and cache keys are byte-identical to
  before. Clients can still send `svg_meta.title` / `svg_meta.description` in
  `ConvertParams` (those alone add a `<title>`/`<desc>`).
- **Server-enforced**: creator, rights and licence are *not* request fields
  (`svg_meta` rejects them), so a client can neither remove nor replace them.
- **Cache-safe**: a digest of the ownership config is part of the result
  filename, so changing it never serves an old, differently-stamped file.
- **Deterministic**: no timestamps (put the year in the rights line).
- **Safe**: values are XML-escaped, stripped of control characters and
  length-capped.
- Applies to `/v1/convert` results (uploads, city maps, airports after
  conversion, CLI) and `/v1/wordmark` (the latter only when an owner is
  configured). City-map/airport *intermediate* SVGs are not stamped; the
  converted result is.

CLI: `--creator`, `--rights`, `--license`, `--license-url`, `--attribution-url`
(override the env for that run), `--title`, `--description`, `--no-title`; see
`docs/img2plot-cli.md`.

## Check a file

```bash
xmllint --noout out.svg && echo "valid XML"
grep -o '<dc:title>[^<]*</dc:title>' out.svg | head
grep -o '<cc:prohibits[^>]*>' out.svg
```

## Third-party sources

Metadata states *your* claim. A drawing converted from someone else's image is
a derivative of it: respect the source's licence (e.g. CC BY-SA requires the
same licence and attribution) and only stamp "all rights reserved" or NC terms
on material you own or may license.
