Mac CD for fund-vista (the prod host since 2026-10-20; the NAS host is decommissioned since 2026-10-21, so the repo no longer mentions it). Chain: GitHub push webhook (repo hook 685475003, events=push only) -> https://ci.linuxadm.hu/hooks/github-ci -> VPS nginx -> autossh tunnel (hu.linuxadm.tunnel-ci-webhook, VPS 127.0.0.1:8290) -> Mac 127.0.0.1:8290 -> the ci-webhook container (~/srv/ci/compose.yml, image ci-webhook:2.9.1-mac) -> ~/srv/ci/hooks/hook-github.sh -> the long-lived deploy runner -> ops/deploy-mac.sh <sha> -> docker build + candidate smoke + swap + live smoke/rollback. No laminar on the Mac (its container was removed); GitHub Actions runs the tests. Knobs (compose env of the webhook, consumed by ops/deploy-mac.sh): FV_CPUS=5.0, FV_MEMGB=4, FV_DATA_DIR=/Users/kissp/srv/fund-vista-data, FV_REPO default /opt/fund-vista (bind of ~/srv/fund-vista). Image tags are fundvista:mac-<short> / fundvista:mac / fundvista:mac-prev (renamed from :nas-* in CR-005; the NAS host is decommissioned). Gotchas: (1) a deploy swaps the prod container, so it kills an in-flight traffic_ingest job; (2) the runner copies ops/deploy-mac.sh before running it, because the deploy rewrites the checkout - and that file - mid-run (it falls back to the old deploy-nas.sh name for one deploy while the rename lands); (3) docker -v sources are resolved by the daemon inside the VM: this Rancher Desktop is Lima-based and shares /Users/kissp over virtiofs at the same path, so host paths work verbatim, and a missing bind source is auto-created, so the data dir must hold a .fund-vista-data marker or the deploy fails loudly; (4) the prod checkout ~/srv/fund-vista is left detached at the deployed sha; (5) deploy logs: ~/srv/ci/cd/logs, build logs ~/srv/ci/cd/build-logs. /data is the host dir (permanent across VM rebuilds); the redis cache volume stays on the engine disk.
