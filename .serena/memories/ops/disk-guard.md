Mac disk guard (CR-009, hu.linuxadm.disk-guard): installed from ops/mac-disk-guard.plist to ~/Library/LaunchAgents/ and run hourly via StartInterval 3600 (all 24 hours, PRUNE=1 RECOVER=1). It checks the host volume floor (GUARD_MIN_FREE_GB default 5, or >=95% used), then prunes regenerable caches (uv, npm, Homebrew, Colima, JetBrains, browsers, updaters) and clean worktrees older than WORKTREE_AGE_DAYS, prunes Docker images/build cache and runs fstrim inside Colima WITHOUT a colima-status gate. If the floor is still breached it restarts Colima once per RECOVERY_RETRY_HOURS (default 6, stamp at ~/.local/state/fund-vista/disk-guard-last-recovery) and retries the VM cleanup; it never touches the checkout, /data, git state or running containers. A broken colima status MUST trigger recovery, not skip cleanup. Recovery runbook: colima stop; colima start; colima ssh -- sudo fstrim -av; then check docker ps, /healthz and POST /v1/citymap/render. Hermetic tests: sh ops/tests/test_mac_disk_guard.sh; shellcheck -s sh ops/mac-disk-guard.sh ops/tests/test_mac_disk_guard.sh.
