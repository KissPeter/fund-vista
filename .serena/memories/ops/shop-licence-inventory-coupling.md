Shop licence-inventory coupling (cross-repo, 2026-10-22, fund-vista #103 / CR-008): the shop repo (KissPeter/pen-pixel-shop) carries this backend as a git submodule and generates its own licence inventory from THIS repo's lockfile — the generator is the shop's `tools/licenses/inventory.py`, it reads `fund-vista/backend/uv.lock` (i.e. this repo's `backend/uv.lock`), and it stamps a digest of that file into the "Inputs" line of the shop's committed `docs/third-party-inventory.md`. The shop's unit lane (`src/lib/third-party-inventory.test.ts`) compares the committed file with a fresh generator run; only the `package-lock.json` digest is masked (npm rewrites that lockfile), so the `uv.lock` digest IS gated. Consequence: every backend dependency bump reddens the SHOP's unit lane until the shop regenerates (`cd <shop> && python3 tools/licenses/inventory.py` — the default output is docs/third-party-inventory.md — and commits it). The same step is needed when the shop moves its submodule pointer. The shop side landed the drift hint (pen-pixel-shop #1158); the backend side is `backend/THIRD_PARTY_NOTICES.md` §D plus the `.github/PULL_REQUEST_TEMPLATE.md` checklist. Rule of thumb: after a `backend/uv.lock` change, say in the PR body that the shop needs a regeneration — the failure otherwise arrives as a red shop CI that names a docs file, not this lockfile. Refs: pen-pixel-shop #1158, #1165, fund-vista #103.
